# The asset compiler: CAD to a Banjo blueprint

Design, 2026-09-15, on `agent/asset-compiler` cut from `1195c78`. This is the
first slice: the stages that need no new dependency are built and measured, and
the stages that do are named with what they would buy.

The owner's spec, in their words: *"Convert each unique part once, preserve the
assembly and its connections, generate inexpensive runtime representations, and
activate detailed material physics only where supported and needed."* The output
is a reusable blueprint carrying geometry, components, materials, connections
and validation results. It is not a picture made of cubes.

## What this slice does and does not do

It does:

- read a declared assembly (parts, instances, connections, rights, units) and a
  triangle mesh per part, with the standard library alone;
- convert each **unique part once**, keyed by the content of its geometry, and
  place it many times by instance transform;
- produce sparse occupancy in the part's own local frame, on the grid the
  engine's `generateVoxelLattice` already uses;
- produce two inexpensive runtime representations: a box decomposition of the
  occupancy for collision, and the mass properties the lattice would compute;
- decide capability flags and record failure categories with measured evidence,
  rather than repairing a part quietly.

It does not:

- read STEP, IGES, JT or any other CAD format. That needs Open Cascade, which is
  not approved. The slice starts from the *canonical assembly* a CAD importer
  would emit, so the importer can be added in front of it without changing
  anything downstream.
- decimate or re-mesh the render geometry. The source triangles are the render
  representation for now.
- run the engine. No part is marked `functionally_tested` here, and no fracture
  or contact claim is made.
- change the engine, the scene schema or the authoring path. Everything below
  that would need those is written down in "What the engine does not have yet"
  rather than built.

## The pipeline

    source  ->  canonical assembly  ->  unique-part conversion  ->  sparse
    occupancy  ->  render/collision  ->  blueprint  ->  instance

1. **Source.** A CAD assembly, a mesh export, or a mesh a person made. Out of
   scope for this slice except as OBJ; see the dependency list.
2. **Canonical assembly.** One document: parts with a mesh and a *declared*
   unit, instances with a transform, connections between instances, and a rights
   record. Units are declared, never inferred: a metre read as a millimetre is a
   thousandfold volume error and nothing downstream can catch it.
3. **Unique-part conversion.** A part is converted once per distinct
   (geometry, cell size, horizon). The key is a hash of the canonical geometry,
   so two parts with different names and identical shape share one conversion.
4. **Sparse occupancy.** Cells whose centre lies inside the solid, in the part's
   own local frame, on the engine's grid: cell (i, j, k) is centred at
   ((i+0.5)h, (j+0.5)h, (k+0.5)h) (`src/matter/Lattice.hpp:100`, `VoxelRecipe`
   at `:110`). Inside is
   decided by the winding number along a scan line, computed independently along
   all three axes and required to agree.
5. **Render and collision.** Render is the source mesh. Collision is a greedy
   box decomposition of the occupancy that covers every cell exactly once, so a
   part that does not need to be editable can be a handful of boxes instead of
   thousands of nodes.
6. **Blueprint.** One JSON document, schema `banjo.asset-blueprint.v1`: parts
   with their geometry, occupancy, proxies, material and mass properties;
   instances; connections; and the validation record.
7. **Instance.** Realising a blueprint on a shared world grid: a whole number of
   cells of translation and a quarter turn of rotation is an exact re-index of
   the part's cells. Anything else needs re-voxelisation in world space, which
   is a different cell count; see the gaps below.

## The package

Flat modules, as the rest of the repository's Python is:

| file | what it is |
|---|---|
| `tools/asset_compiler.py` | the converter, and its CLI |
| `tools/asset_fixtures.py` | the fixtures, generated by code, and their assembly document |
| `tests/asset_compiler_tests.py` | the suite |
| `docs/asset-compiler.md` | this document |

Nothing imports the engine. `src/matter/Lattice.hpp` is not in the public
`include/` tree, so the generator is reachable from outside only through the C
API or a new binding, and neither exposes it today (`include/banjo/banjo.h` has
no voxel-recipe entry point). The compiler therefore *reproduces* the grid
convention and the neighbour rule rather than calling them, and the tests pin
the reproduction to the numbers the C++ states.

## Capability flags

A flag is set only when this slice measured the thing it claims.

| flag | set when |
|---|---|
| `visual` | the mesh parsed and has triangles |
| `static_collision` | the mesh is a closed solid of positive volume, and the box decomposition covers its occupancy |
| `movable_rigid` | `static_collision`, and a known material gives mass, centre of mass and inertia |
| `editable_voxels` | `movable_rigid`, the occupancy is inside the cell budget, and no feature was lost below the resolution |
| `articulated` | a declared connection of an articulated kind joins two instances whose occupancies touch |
| `powered` | never set by this slice: the assembly document has no power declaration and the engine's machines are authored elsewhere |
| `functionally_tested` | never set by this slice: it needs an engine run |

## Failure categories

Every failure carries a measured detail, and a failure never repairs the part.

| category | raised when |
|---|---|
| `rights_unverified` | the assembly declares no rights record; the blueprint is marked not publishable |
| `units_ambiguous` | a part declares no unit, or one outside {m, cm, mm, in} |
| `invalid_solid` | the mesh is not closed, or the three axis scans disagree about a cell |
| `feature_below_resolution` | the part's thin dimension is below one cell, measured as a volume-weighted thickness |
| `required_gap_lost` | two occupied cells within the bond horizon are separated only by empty cells, so the generator would bond through the void |
| `material_unknown` | the part declares no material, or one outside the engine's catalogue |
| `connection_ambiguous` | a declared connection joins instances that do not touch, or two instances share cells with nothing declared |
| `physics_budget_exceeded` | the cells exceed the budget the target lane will run |
| `functional_test_failed` | declared for the format; never raised here, because nothing is run |

## The budgets this slice quotes

- **4,000,000 cells**: `generateVoxelLattice` refuses a larger recipe
  (`src/matter/Lattice.cpp:350`). That is the generator's own guard, not a
  statement that such an object belongs in a live room.
- **16,000 cells**: what the playground's lattice lane will accept for a whole
  scene (`playground/fracture_lab.py`, `ALGORITHMS["lattice"]["max_cells"]`),
  every body in that scene sharing one cell size.
- **800 cells**: the per-object budget of the network lane
  (`playground/network_admission.py`, `OBJECT_CELL_BUDGET`).

The compiler's default budget is the room's 16,000, because that is the number a
part has to live inside to be picked up and dropped rather than benchmarked.

## Why the gap check exists

`buildBonds` (`src/matter/Lattice.cpp:113`) bonds a node to every occupied
neighbour within the horizon, filtered only by grid distance. There is no test
that the straight segment between the two cells crosses empty space. Material on
the two sides of a slot narrower than the horizon is therefore bonded through
the void, and the slot is welded shut in the lattice while still looking like a
slot. This slice does not change the generator. It detects the case, counts the
bonds, and refuses the part with `required_gap_lost`, so a moving joint is never
compiled into a solid block by accident.
