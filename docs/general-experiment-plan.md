# General experiment platform execution plan

The playground must compile requests into inspectable physical setups, execute
only supported laws, and expose the outcome in 3D. A valid JSON response or a
moving rendering is not proof that an experiment was performed correctly.
This plan extends G02/G03/G08/G09 and preserves every existing goal and mechanic.

| Stage | Deliverable | Acceptance |
|---|---|---|
| 1. Composable authoring | General scene and comparative drop declarations, explicit SI dimensions, orientations, spin, gravity and support | Public packages preserve every requested supported setting; invalid combinations reject before physics |
| 2. Capability negotiation | Supported/experimental/unavailable distinctions and useful errors | Unsupported requests cannot run substituted geometry or claim missing material laws |
| 3. Experiment inspection | Same native run supplies report and sampled 3D states, custom controls change declared inputs | Native/report parity; reruns retain other inputs; visible limits and measurements |
| 4. Diverse request evaluation | Seeded varied prompts passed through real GPT and native execution | Per-prompt intent assertions, generated settings, status, playback availability and timings retained; failed cases count as failures |
| 5. Thin-structure representation | Plate/shell bending or demonstrably converged volumetric alternative | Analytical bending, thickness/mesh refinement, contact response and matched glass/oak/iron controls |
| 6. Unified impact and material response | Contact, elasticity/plasticity, crack initiation/propagation and fragment handoff share state and time | Reactions, momentum/work ledger, rollback and refinement; real thin-glass drop comparisons with declared uncertainty |
| 7. Runtime qualification | Local active work, conservative representation switching, measured scheduling/capture/render budgets | Repeated representative world loads meet a declared accuracy/frame budget without suppressing physical work |

Execute stages 1–4 first using existing experimental native laws. Stages 5–7
require new physics and measured validation; do not mark them complete through
authoring or presentation changes. Thin calibrated shattering remains unavailable
until its representation and solver gates pass. Experimental network damage may
run within its admitted range with an explicit unresolved result.

Use glass, oak and iron in every comparative drop. Random request evaluation
must include varied dimensions, heights, supports, projectile shapes, custom
motion/gravity, pressure references, and deliberately unsupported physics.
Separate request fidelity, execution success, numerical resolution, and material
validation in the scorecard. No LLM call occurs inside the physics clock.

Stages1–4 now have bounded implementations and [recorded evaluation](general-experiment-checkpoint.md).
The random evaluation caught real semantic errors; they were fixed and rechecked,
with all failed batches preserved. Stage5 has an initial6mm volumetric diagnostic
and three failing timestep runs, not a completed thin-structure representation.
Stages6–7 remain open physics and performance work. No full platform goal is complete.
