## Change

The autonomous character now consumes the same private processing readiness
returned by player guidance and Market. It can choose a supported recipe using
its own carried/stored material, approach the machine, stop/select, store raw
ground, load the input, power on and explicitly watch the actual batch. The
previous catalog considered only the currently selected recipe and accumulated
unrelated advanced prerequisite blockers. Consequently a depleted copper intake
could stop a character already carrying usable sand.

Readiness includes measured carried volumes, owned raw lots, input locations,
current recipe/power, native charge and current observation state. Displayed
possibilities award no output or knowledge. Execution retains ordinary source,
ownership, distance, heat/work, native timing and durable-save gates.

Readiness also checks the same machine-to-pile reach rule used by processing.
A generated stepped-map furnace physically tips/slides away from its fixed
input/output locations in the retained experiment. The prior controller watched
it repeatedly while the real routine reported that its intake was out of reach.
Guidance now reports that obstruction. No body is pinned, relocated or given
new friction to make the test succeed, and no material pile follows it magically.

Processing writes retain their receipt id, source, revision and quantity before
execution. Unknown/lost replies keep that request and preempt later transfers,
even if the goal changes. After reopening the same authenticated world,
delivery/selection binds only the transport session to the current connection;
receipt semantics remain unchanged. Explicit pre-transfer refusals refresh the
plan. A browser-discovered fractional load refusal also prompted rounding down
to the delivery API's whole-microgram quantity, without overdrawing the source.
